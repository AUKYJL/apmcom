# Отчёт за недели 1–4

Запуск из корня проекта в существующем окружении backend:

```bash
backend/.venv/bin/python -m pip install -r report/requirements.txt
backend/.venv/bin/python report/generate_report.py
```

PostgreSQL должен быть запущен и содержать данные проекта. Подключение берётся
из настроек Django (`backend/.env`, переменные окружения имеют приоритет).
Скрипт читает БД в одной транзакции `REPEATABLE READ READ ONLY`.
Результат: `report/Лесная Чашка — отчёт недели 1-4.xlsx`.
Исходный шаблон не перезаписывается, готовый отчёт заменяется только после проверки.

## Правила расчёта

- Период фиксирован: 01.12–27.12.2026 включительно, `Europe/Moscow`.
  Недели: 1–6, 7–13, 14–20 и 21–27 декабря.
- Сотрудники (`is_staff`) и шесть технических CRM-кодов из `EXCLUDED_CODES`
  исключаются из всех показателей. Список нужно поддерживать при появлении новых
  технических аккаунтов; `is_active` для исключения не используется.
- Регистрации — по `User.date_joined`. Участники — уникальные пользователи
  с чеками недели по дате загрузки `Receipt.created_at`, независимо от статуса.
- Новые участники — по первому чеку за всю историю, независимо от статуса.
  Участие в прошлой акции (H) считается только среди новых участников недели (F).
- Загруженные чеки — все статусы; принятые — только `accepted`.
  Пачки и SKU — сумма `ReceiptItem.quantity` в принятых чеках, по трём форматам.
  Причины отклонения — только `rejected`, по заголовкам шаблона.
- На листе «Участники» — одна строка на участника с чеками периода:
  CRM-код (строка из 20 цифр), дата регистрации, количества чеков,
  сохранённые баллы и призы, участие в прошлой акции. NULL приза означает ноль.
  ФИО, email, телефоны, фото и фискальные реквизиты из БД не выбираются.

## Особенности и проверки

SQL находится в `queries.sql`. Runtime-проверки контролируют качество данных,
баланс статусов, суммы по неделям и дням, причины отклонения, SKU и итоги участников.
Неизвестные причины/SKU и некорректные CRM-коды прерывают выгрузку.
После обычного `openpyxl.save()` проверяются пять листов, заполненные ячейки,
исходные формулы, план, стили, объединения, ширины столбцов и наличие диаграммы.

План и все формулы оставлены строго как в шаблоне, будущие недели пусты.
Excel пересчитает формулы при открытии: openpyxl не вычисляет их и не сохраняет кэш
результатов. В будущих неделях `Тотал!G13:G17` исходные формулы дают `#DIV/0!`.
G считает принятые чеки на участника, хотя заголовок говорит о загруженных;
E18 суммирует недельные уникальные показатели, а не уникальных людей периода;
M18 усредняет недельные проценты. Эти особенности шаблона не исправляются по ТЗ.
Уникальные участники за четыре недели — число строк данных листа «Участники»
и `participants` в итогах CLI.
